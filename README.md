# Продажа обуви

Учебный проект по МДК 04.01 «Внедрение и поддержка компьютерных систем».
Я выполнил девять практик по индивидуальному листу: по три из каждого раздела.
Приложение использует Python, SQLite и обычный JavaScript, без внешних зависимостей для запуска.

## Запуск

Нужен Python 3.8 или новее. В терминале перейдите в папку репозитория:

```sh
python3 server.py
```

Откройте http://localhost:8000. Остановка: Ctrl+C.
Если порт занят: `python3 server.py --port 8001`, затем http://localhost:8001.
В репозитории уже есть `shop.db` с демонстрационными данными.

Чтобы создать новую демонстрационную базу, не меняя готовую:

```sh
python3 create_db.py --db demo.db
python3 demo_data.py --db demo.db
python3 server.py --db demo.db
```

`create_db.py` создаёт схему и не удаляет имеющиеся записи. `demo_data.py` заполняет только базу без товаров; повторное заполнение отклоняется.

## Как проверить интерфейс

Вход выполняется по логину без пароля, как указано в практике 2.2.

| Логин | Роль | Возможности |
| --- | --- | --- |
| admin | Администратор | Просмотр заказов, изменение даты, удаление позиций |
| manager | Менеджер | Список и состав заказов |
| client1, client2, client3 | Клиент | Просмотр товаров |

После входа менеджером или администратором нажмите «Заказы», затем «Открыть».
Администратор меняет дату, удаляет позицию и нажимает «Сохранить изменения».
До сохранения изменения остаются в окне; закрытие окна их отменяет.
После сохранения удалённое количество возвращается на склад, сумма пересчитывается.
Цена позиции хранится на момент заказа. Пустой заказ сохраняется с суммой 0.

Каркас содержит кнопку пустой корзины. Покупка, импорт XLSX, поиск/фильтры каталога и ручное создание заказов не входят в выбранные работы. Вход и базовый список товаров нужны для проверки панели заказов. Проверка прав выполняется также на сервере. Сессии действуют до остановки сервера; после обновления страницы нужно войти снова. Приложение предназначено для локальной учебной работы.

## Проверки из терминала

```sh
sqlite3 shop.db < queries.sql
python3 -m unittest discover -s tests -v
curl http://localhost:8000/
curl 'http://localhost:8000/api/login?login=manager'
```

Для проверки DDL отдельно: `sqlite3 empty.db < schema.sql`, затем `sqlite3 empty.db '.tables'`.
`sqlite3` CLI нужен только для запуска SQL-файлов из терминала; приложение использует встроенный модуль Python.
Тесты API создают отдельные временные базы и не меняют `shop.db`.
В `tests/browser_check.cjs` находится дополнительная браузерная проверка. Только для неё нужен Playwright (`npm install --no-save playwright` и `npx playwright install chromium`). Команда: `BASE_URL=http://127.0.0.1:8000 node tests/browser_check.cjs`. При необходимости задайте `BROWSER_PATH` до исполняемого файла Chrome. На время проверки не редактируйте `shop.db`: сценарий возвращает его исходную копию после завершения.
